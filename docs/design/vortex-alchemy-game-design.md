# Vortex Alchemy 游戏设计与核心循环

版本：0.1  
日期：2026-10-20  
目标平台：桌面与移动浏览器  
目标单局时长：约 3–6 分钟

## 一句话定位

在会自行结晶的炼金台上旋转 2×2 材料，把同色同阶的器皿压成更高阶器具，用连续反应换取倒计时，最终在黑、白、红、黄的顶点合成圣杯。

玩家扮演的不是“点格子消消乐”的旁观者，而是一位在时间压力下现场调配反应的炼金术士。每次旋转都像拨动一只精密机关：四格同时转动，反应一旦开始，材料会自己继续熔合。

## 核心体验

- 主要动词只有三个：观察、选择 2×2 区域、旋转。
- 玩家每 1–3 秒做一次决定，不需要拖拽或交换棋子。
- 一次旋转可能引出多段自动连锁，连锁越深，获得的时间越多。
- 玩家要同时追求三层目标：
  1. 现在活下去：优先做容易触发的合并，把倒计时续上。
  2. 做得更漂亮：把高阶材料凑到一起，追求长连锁。
  3. 完成仪式：收集四色四阶宝石，合成圣杯。
- 合并后棋子会沿列向下落，新棋子从顶部补入；下落后的位置关系会继续参与连锁判定。

## 核心循环

```text
观察棋盘
  ↓
找到一个值得转动的 2×2
  ↓
点击中心，四格顺时针旋转
  ↓
同色同阶自动合并，棋子下落并从顶部补入新棋子
  ↓
若新棋子继续形成合并，进入下一段连锁
  ↓
合并与连锁把时间加回来
  ↓
时间尚未耗尽，继续观察棋盘
  ↓
时间归零，结算分数、最长连锁与圣杯数量
```

一局的情绪节奏应当是这样：前 20 秒熟悉容器形状与颜色；中段开始主动布局二阶、三阶材料；高潮来自“下落的棋子刚好接上”“连锁把濒死时间救回来”“四色宝石终于围成 2×2”。

## 棋盘与棋子

棋盘固定为 8×8，共 64 格，可点击的 2×2 中心共有 7×7 个。

颜色只有五种：

| 类型 | 表现 | 规则身份 |
| --- | --- | --- |
| 黑 | 午夜墨色玻璃与新月刻纹 | 普通四色之一 |
| 白 | 骨白玻璃与珍珠星刻纹 | 普通四色之一 |
| 红 | 朱砂玻璃与火焰滴刻纹 | 普通四色之一 |
| 黄 | 金色玻璃与日轮刻纹 | 普通四色之一 |
| 万能 | 紫色黏胶与旋涡核心 | 只替代一阶棋子 |

阶级只有四阶：

| 阶级 | 名称 | 形状要求 |
| --- | --- | --- |
| 一阶 | 试管 | 细长、易辨认 |
| 二阶 | 烧杯 | 有明显倾倒口 |
| 三阶 | 圆底烧瓶 | 宽圆底、细颈 |
| 四阶 | 宝石 | 切面明确、不再走容器轮廓 |

形状承担阶级辨识，颜色承担属性辨识。不能只靠颜色区分，否则色弱玩家会失去一半信息。

## 转动规则

- 点击任意 2×2 的中心，四格棋子顺时针旋转 90°。
- 桌面端可选：右键或 `Shift` + 点击逆时针旋转。
- 触屏端默认点击顺时针；长按可选逆时针，避免把两种方向混成一次误触。
- 旋转动画期间锁定输入，避免玩家在连锁中继续操作。
- 圣杯可以随 2×2 一起旋转，但永远不会被当作材料消耗。
- 常态不显示旋转转盘。只有鼠标悬停、键盘聚焦或手指按住时，才在对应 2×2 中心出现低对比提示。

> 设计假设：圣杯保持可旋转，是为了避免多个圣杯迅速把邻近的旋转中心全部锁死。若后续希望它成为不可移动障碍，只需在旋转合法性检查中增加一条排除规则。

## 合并规则

### 普通合并

一个 2×2 中的四个棋子满足“同色、同阶、阶数在 1–3”时，合并为高一阶的同色棋子：

- 四个一阶红试管 → 一个二阶红烧杯。
- 四个二阶白烧杯 → 一个三阶白圆底烧瓶。
- 四个三阶黄烧瓶 → 一个四阶黄宝石。

四阶不能再按同色同阶继续升阶。四个同色四阶不会合并，也不会消失。

### 合并点的定义

一次旋转同时移动四个棋子，因此“哪一个是触发的棋子”不能靠动画先后决定。本稿采用稳定、可复现的定义：

> 合并点取匹配 2×2 的左上格。它是按顺时针扫描时第一个被检查到的格子。

这个定义只影响合并结果落在哪个格位，不改变时间收益。若你希望改成“最后转入匹配块的那颗棋子”，实现时应替换独立的 `pickMergeAnchor()`，不要改动其他规则。

合并完成后：

- 高一阶棋子留在合并点。
- 四格被消耗后，所有棋子沿所在列向下压实。
- 每列顶部的空位由新棋子从棋盘上方补入，新棋子会逐格下落。
- 下落和补子完成后，立即用落定后的完整盘面重新检查全盘，不需要玩家再点一次。
- 下落时保留棋子所属列，不会横向滑动。

### 连锁

一次旋转之后发生的所有自动合并构成同一串连锁：

1. 第一次合并记为连锁 1。
2. 棋子落定并从顶部补子后若再次形成合并，记为连锁 2。
3. 连锁持续到全盘没有合法合并为止。
4. 玩家下一次主动旋转时，连锁计数归零。

每段连锁都会立刻加时间。若倒计时在连锁动画中见底，先让当前连锁完整结算；如果连锁加回时间，本局继续。

### 万能棋子

紫色万能棋子只能替代一阶棋子，不能替代二阶、三阶或四阶。

合法例子：

- 三颗同色一阶 + 一颗万能 → 该颜色二阶。
- 两颗同色一阶 + 两颗万能 → 该颜色二阶。
- 一颗同色一阶 + 三颗万能 → 该颜色二阶。
- 四颗万能 → 圣杯。

非法例子：

- 万能替代二阶或更高阶。
- 万能同时补出两种不同颜色。
- 三颗不同颜色的一阶 + 一颗万能。

### 圣杯

圣杯采用“四色齐全”的仪式配方，而不是任意四个四阶：

> 2×2 中恰好有一颗黑四阶、一颗白四阶、一颗红四阶、一颗黄四阶时，四个棋子合成为一个圣杯。

这里要区分两件事：圣杯本身可以被制作出来；“圣杯无法合成”指的是它不能被当作材料再次参与任何合成，并不是说圣杯无法获得。

圣杯也遵守同样的落位与补子规则：

- 圣杯落在匹配块左上格。
- 其他棋子向下压实，顶部空位由新棋子补入。
- 立即获得大笔时间奖励。
- 圣杯不能作为任何后续合成的输入，也不会被其他配方消耗。
- 四个圣杯放在一起不会合并，也不会移出棋盘。
- 圣杯仍可随所在 2×2 一起旋转，只是永远只作为障碍性奖励留在棋盘上。
- 四颗万能棋子的特殊配方也直接合成圣杯。

这个配方让玩家在追时间之外还有一个可以主动经营的长线目标。四色宝石需要分别从四条颜色线升到四阶，再被转到同一个 2×2 里。

## 合并结算顺序

旋转结束后，可能出现互相重叠的多个合法 2×2。为避免同一棋子被重复消耗，本稿规定“一次只结算一组，再重新扫描”。

候选组优先级：

1. 圣杯配方。
2. 结果阶级更高者。
3. 距离上一次合并点更近者。
4. 更靠上的行。
5. 更靠左的列。

伪代码：

```ts
function resolveAfterRotation(board: Board, rotation: Rotation): CascadeResult {
  let chain = 0;
  let lastAnchor: CellPos | null = null;

  while (true) {
    const candidates = findAllValidGroups(board);
    if (candidates.length === 0) break;

    const group = chooseByPriority(candidates, lastAnchor);
    const anchor = pickMergeAnchor(group);
    const merged = createMergedPiece(group);
    const before = cloneBoard(board);

    consumeAllFourCells(group);
    board.set(anchor, merged);
    const gravity = applyGravityAndRefill(board, rng);
    const after = cloneBoard(board);

    chain += 1;
    lastAnchor = anchor;
    awardTime(merged, chain);
    awardScore(merged, chain);
    recordEvent({ before, group, merged, ...gravity, after });
  }

  return { board, chain };
}
```

把重叠匹配拆成连续连锁，会让画面自然形成“反应继续传播”的节奏，也避免结算顺序藏在动画层里。

## 时间系统

时间既是生存资源，也是唯一的压力来源。

默认时间参数：

| 事件 | 默认加时 |
| --- | ---: |
| 一阶 → 二阶 | +2.0 秒 |
| 二阶 → 三阶 | +4.0 秒 |
| 三阶 → 四阶 | +7.0 秒 |
| 合成圣杯 | +45.0 秒 |
| 开局倒计时 | 90.0 秒 |

连锁倍率：

```text
倍率 = 1 + 0.25 × min(连锁序号 - 1, 6)
```

因此第 1 段连锁是 1.00 倍，第 2 段是 1.25 倍，第 7 段及以后封顶为 2.50 倍。

```text
实际加时 = 本次合并基础加时 × 连锁倍率
```

倍率封顶不是为了阻止长连锁，而是避免极端随机局把倒计时一次性推到几分钟，削弱后续压力。连锁序号本身仍可继续增长。

一个示例：

```text
连锁 1：一阶 → 二阶，+2.0 秒
连锁 2：二阶 → 三阶，+4.0 × 1.25 = +5.0 秒
连锁 3：三阶 → 四阶，+7.0 × 1.50 = +10.5 秒
连锁 4：四色四阶 → 圣杯，+45.0 × 1.75 = +78.75 秒
```

倒计时在未暂停、未打开设置、页面处于前台时持续减少。暂停、设置面板、标签页失焦时停止计时。

## 分数

分数是第二层反馈，不影响生存。默认分值：

| 结果 | 基础分 |
| --- | ---: |
| 二阶 | 100 |
| 三阶 | 300 |
| 四阶 | 900 |
| 圣杯 | 5000 |

实际得分同样乘以连锁倍率。最佳成绩记录分数、最长连锁与圣杯数量。

## 局内界面

棋盘居中是唯一需要长时间凝视的区域，其余信息应退到边缘。

```text
┌──────────────────────────────────────────┐
│ 分数           00:58.4          暂停  设置 │
│                                          │
│            ┌────────────────┐            │
│            │                │            │
│            │    8 × 8 棋盘   │            │
│            │                │            │
│            └────────────────┘            │
│                                          │
│ 连锁 ×3     圣杯 0       当前目标：四阶宝石 │
└──────────────────────────────────────────┘
```

- 倒计时是最大的常驻数字，低于 10 秒时只让数字与边框缓慢脉动，不让整个屏幕闪红。
- 连锁信息只在连锁发生期间展开，结束后回到安静状态。
- 常态不铺满旋转转盘。鼠标悬停、键盘聚焦或手指按住时，四个角先出现低对比的括号，中心转盘以约 25%–35% 不透明度、55%–65% 缩放和 2–3px 模糊淡入；指针移开后在约 120ms 内淡出。
- 转盘只负责暗示“这里可以转”，不能盖住棋子，也不能比倒计时更抢眼。首次教学可清晰展示一次，随后同样退回弱提示。
- 新棋子、合并、连锁分别使用不同强度的反馈；普通旋转不触发屏幕震动。
- 主菜单只有“开始实验”“设置”“玩法说明”，第一局直接可开始。
- 设置打开时自动暂停；设置关闭后显示 3 秒再接续，避免玩家刚回来就手忙脚乱。

## 难度与调参原则

- 一阶棋子必须占绝对多数，否则棋盘会很快被高阶材料塞满，旋转失去意义。
- 二阶棋子是“小惊喜”，不能成为主循环的主要来源。
- 万能棋子价值很高，既能让布局更宽容，也能直接凑出圣杯；出现率要低。
- 初始棋盘不预置任何可合并的 2×2，避免开局白送连锁。
- 初始棋盘至少要存在一个能在一次旋转后形成合并的区域，避免开局无事可做。
- 时间收益的调整优先看“平均每次合并能否抵消 3–5 秒观察时间”，而不是只看单次加时。
- 自定义规则不进入默认排行榜，避免用极高加时刷分。

## 技术方向

采用 Phaser 3 + TypeScript + Vite。

理由：

- 棋盘是标准 2D 网格，Phaser 的精灵、补间、输入与场景管理足够直接。
- 旋转、补子、粒子与倒计时都可以稳定跑在浏览器里。
- 设置、HUD、弹窗、文本与滑杆更适合 DOM，不必塞进 Canvas。
- 模拟层可以脱离 Phaser 单测，后续也可以换渲染层而不用重写规则。

### 模拟状态

模拟层只保存可序列化数据：

```ts
type CoreColor = "black" | "white" | "red" | "yellow";

type Piece =
  | { id: number; kind: "core"; color: CoreColor; tier: 1 | 2 | 3 | 4 }
  | { id: number; kind: "wildcard" }
  | { id: number; kind: "grail" };

type RunState = {
  board: Array<Piece | null>;
  seed: string;
  status: "ready" | "playing" | "resolving" | "paused" | "game-over";
  timeLeftMs: number;
  score: number;
  chain: number;
  maxChain: number;
  grails: number;
};
```

Phaser 场景只做三件事：

1. 把 `RunState` 映射成精灵位置与动画。
2. 把点击坐标转换成旋转动作。
3. 播放旋转、合并、下落、顶部补子与连锁反馈。

规则判断、重力压实、补子顺序、加时与游戏结束全部在模拟层完成。

### 随机与复现

- 运行时使用可注入种子的伪随机数生成器。
- 同一棋盘、同一操作顺序、同一种子必须得到同一结果。
- 测试不依赖 Math.random，避免偶尔失败的用例。
- 重力按列从底部向上压实；顶部补子按列从左到右、行从上到下生成。
- 每个连锁事件保存合并前盘面、下落位移、补子起点与落定后盘面，渲染层不自行推断规则。

### 性能边界

- 每局只有 64 个棋子，绘制压力很小。
- 棋子使用一张透明图集切片，避免散图加载。
- 普通旋转只移动四个容器；连锁期间复用粒子对象池。
- 高刷新率屏幕上把补间目标固定在约 60 FPS 的视觉节奏，不让 144Hz 改变判定结果。
- 页面失焦立即暂停计时。

## 美术方向

关键词：简洁明快的卡通消除风、粗描边、饱和玻璃色、少量高光、黄铜机关、深紫棋盘。

基础 HUD、设置面板和文字仍由 DOM/CSS 完成。额外美术只负责可选的装饰底板、按钮边框、图标与背景，不把文字、数字或按钮文案烘焙进图片。这样便于响应式布局和无障碍，也不会因为改一个数字就重新生成整张图。

颜色不能是唯一线索：

- 阶级靠容器剪影区分，四个阶级在小尺寸下也要一眼看出差别。
- 颜色靠明显色相与简单刻纹共同区分，不使用复杂雕花。
- 黑色棋子使用炭黑玻璃、亮紫蓝高光和浅色粗描边，不能变成没有轮廓的黑块。
- 白色棋子使用珍珠白、天空蓝阴影与深色粗描边，不能消失在浅色背景里。
- 不采用水彩、做旧纸张、复杂复古纹章或暗黑童话插画风；棋子应像可以直接放入消除游戏网格的成品图标。

旋转转盘是交互提示图，不作为常驻徽章。游戏内应通过透明度、缩放和轻微模糊降低存在感；只有教学页、帮助页或首次操作时清晰展示。

原图 `sheet_alchemy.png` 为 1536×1024，但器物并未严格按 256×256 格居中，直接切片会产生明显横向错位。运行时使用 `src/assets/sheet_alchemy_centered.png`：先按透明像素识别每个器物及附属气泡、星芒，再把完整轮廓居中放回 6×4 格。可运行 `npm run sprites:normalize` 重建。

## 第一版范围

第一版必须包含：

- 8×8 棋盘与 7×7 可点击旋转中心。
- 点击顺时针旋转，可选的逆时针操作。
- 同色同阶合并、重力下落、顶部补子、自动连锁。
- 四色四阶圣杯与四万能圣杯。
- 每段合并加时、连锁倍率、倒计时与暂停。
- 设置页中的时间、补子权重、操作与辅助选项。
- 桌面与手机布局、游戏结束结算、本地最佳成绩。
- 用占位图形也能完成一次完整试玩。

第一版不包含：

- 关卡战役、剧情章节、成就系统。
- 在线排行榜、账号、云存档。
- 3D、复杂着色器或逐帧角色动画。
- 多语言与整套配音。

## 验收用例

### 规则

- 四个同色同阶一、二、三阶分别升到二、三、四阶。
- 四个同色四阶不合并。
- 黑白红黄各一个四阶合成圣杯。
- 四个万能合成圣杯。
- 圣杯不能再次作为材料参与合成；包含圣杯的 2×2 不会触发合并，圣杯数量也不会减少。
- 万能只替代一阶，不替代高阶。
- 合并点固定，另外三格各补一个新棋子。
- 棋子落定并补子后能自动继续结算，不要求玩家二次点击。
- 一次旋转造成多处重叠匹配时，不会重复消耗同一棋子。
- 连锁时间倍率与封顶正确。
- 倒计时见底时，正在结算的连锁能够完整结束并有机会续命。
- 暂停、设置和切后台期间时间不减少。

### 设置

- 时间与补子参数在下一次开局生效。
- 权重会归一化并显示明确数值。
- 输入超出范围时钳制到合法范围，并给出可见提示。
- 自定义规则局与默认最佳成绩分开记录。

### 浏览器

- 1440×900 与 390×844 下棋盘完整可见，HUD 不遮挡可点击中心。
- 鼠标、触屏和键盘焦点都有明确反馈。
- 常态看不到旋转转盘；悬停、按住或键盘聚焦时只出现低透明度模糊提示，移开后迅速淡出。
- 设置打开时棋盘输入停止，关闭后有三秒缓冲。
- 减少动态效果开启时，旋转与合并仍可理解。
- 连续快速点击不会在结算期间插入额外旋转。

## 建议实现顺序

1. 先写纯 TypeScript 棋盘、合并、连锁、补子与种子随机，并配单测。
2. 接 Phaser 绘制和旋转输入，用占位色块跑通完整一局。
3. 加 DOM 倒计时、分数、暂停、设置与结算。
4. 接入透明图集、合并特效与连锁反馈。
5. 做桌面、手机和减少动态效果的浏览器验收。
6. 再调默认时间与补子概率，不先凭感觉堆特效。

## 需要确认的设计假设

以下五项是本稿为了能直接实现而选定的默认答案，改动成本都不高：

1. 圣杯配方是“黑、白、红、黄各一个四阶”，不是任意四个四阶。
2. 合并后所有棋子沿列下落，新棋子从顶部补入。
3. 圣杯可以被制作出来并随旋转移动，但不能作为材料再次参与合成。
4. 点击中心默认顺时针；逆时针是桌面右键或触屏长按的额外操作。
5. 合并点固定取匹配块左上格，以保证跨设备和回放一致。
